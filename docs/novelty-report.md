# 題材重複調査レポート: `Scanner.nextInt()`の直後に`nextLine()`が空行を返す

## 調査対象

| 項目 | 内容 |
| --- | --- |
| 対象言語 | Java 21 |
| 難易度プロファイル | 実践・上級 |
| 候補題材 | 数値トークンの直後に`nextLine()`を呼ぶと行末だけを読み、次行にある氏名を空文字列として扱う問題 |
| 観測可能な契約 | `"28\nAda Lovelace\n"`から氏名を登録し、`REGISTERED`、最後の氏名`Ada Lovelace`、登録件数1を得るべきだが、バグ状態では空氏名拒否・null・0となる。 |
| 直接原因 | `nextInt()`後に残る行末を消費せず、最初の`nextLine()`を氏名行として扱うこと。 |
| カタログ更新日時 | Repository Catalog（`/home/ubuntu/repository-catalog`）は存在しなかったため更新・検証は実施不能。代替として、ユーザー指定の`tonbiattack/qiita`を取得し、Java・Scanner・nextInt・nextLine・標準入力・改行・空行を本文とパスから検索した。 |
| 検索語 | `Java`, `Scanner`, `nextInt`, `nextLine`, `標準入力`, `改行`, `入力空行` |

Repository Catalogが利用できなかったため、このレポートの新規性判断は指定コンテンツリポジトリを対象とします。カタログに未登録のローカル専用教材までは保証できない限界を明示します。

## 結論

**作成する。**

指定コンテンツリポジトリには、`Scanner.nextInt`と`nextLine`の混在、数値後の残存改行、または次行氏名の取りこぼしを直接原因として、登録結果・氏名・件数を扱う記事・教材は見つかりませんでした。
